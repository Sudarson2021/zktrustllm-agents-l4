\subsection{Stage E/F: n8n-Based Multimodel and Multi-Agent Evaluation}
\label{subsec:stage-ef-n8n-evaluation}

To address the need for a reproducible automation workflow and quantitative multimodel evaluation, we implemented a Stage E/F n8n-based evaluation workflow around the local ZKTrustLLM-Agents L4 artifact. The workflow connects a local evidence runner to three model providers, namely Claude Fable 5, DeepSeek, and Mistral, and evaluates their behaviour on evidence-grounded claim-boundary tasks. The workflow is intentionally scoped to local artifact evaluation: it measures model/tool orchestration behaviour around the frozen ZKTrustLLM-Agents evidence package rather than claiming production O-RAN deployment, packet-capture network benchmarking, public-chain benchmarking, or full media-plane QoE validation.

Stage E evaluates single-agent tool-scenario behaviour. The three Stage E scenarios are evidence-summary generation, claim-boundary review, and policy-ladder checking. Each scenario requires the model to produce structured JSON grounded only in the frozen artifact evidence, including the Stage B, Stage C, and Stage D-real execution summaries. The evaluator records valid JSON rate, task accuracy, latency, configured estimated cost, failed runs, and output consistency. This stage tests whether individual models can correctly summarise the local evidence and reject unsupported claims such as production O-RAN validation or a 240-run six-variant ablation.

Stage F evaluates multi-agent orchestration behaviour using five higher-level cases: task decomposition, agent collaboration, failure recovery, verification-agent checking, and model-disagreement resolution. These cases represent the supervisor-requested multi-agent extension, but are still evaluated conservatively as local model/tool orchestration scenarios. The final n8n canvas execution contains 90 model-assisted runs: 45 Stage E single-agent runs and 45 Stage F multi-agent runs across Claude Fable 5, DeepSeek, and Mistral. At the raw-run level, the evaluation produced 89 passing runs, 1 partial run, and 0 failed runs, with valid JSON produced in 90/90 runs.
